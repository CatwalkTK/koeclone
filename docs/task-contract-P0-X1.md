# タスク契約 P0-X1: PoC計測スクリプト

| 項目 | 内容 |
|---|---|
| 契約ID | P0-X1 |
| 文書所有者 | Claude（唯一の指揮官）。本文書の変更はClaudeのみが行う |

## 1. 目的

参照WAVと評価文リストを受け取り、デバイス指定（`cpu` / `mps`）で音声合成を実行し、
所要時間・RTF（Real-Time Factor）・ピークメモリ・出力パス・ウォーターマーク検出結果を
JSONで出力するPoC計測スクリプトを作成する。

実行自体（実モデルでの計測）はClaudeがP0-C2で実施する。本タスクの成果物は
スクリプトと、その引数解析・結果JSONスキーマを検証する単体テストである。

## 2. 所有ファイル（このタスクで作成・変更してよいファイル）

- `scripts/poc_generate.py`
- `tests/unit/test_poc_args.py`

上記2ファイル以外の作成・変更・削除は一切禁止する。

## 3. 変更禁止（違反した場合は契約違反として差し戻す）

- 所有ファイル以外の全ファイル。特に `pyproject.toml`、`uv.lock`、`docs/` 配下、`.gitignore`
- 一切のGit操作: `git add`、`commit`、`checkout`、`switch`、`merge`、`rebase`、`reset`、`stash`、worktree操作
- 依存関係の導入・更新・削除（`pip install`、`uv add`、`uv sync` 等）。依存導入はClaudeのみが行う
- モデル重みのダウンロード・更新処理をスクリプトに書くこと（モデルはロードのみ。取得はClaudeがP0-C1で実施済み）
- ネットワークへ音声・テキストを送信するコードの追加

## 4. RED（先に書くテスト）

`tests/unit/test_poc_args.py` に以下を先に書き、スクリプト未実装の状態で失敗することを確認する。

1. 引数解析:
   - デバイス指定 `--device cpu` / `--device mps` を受理し、それ以外（例: `cuda`、空文字）を拒否する
   - 参照WAVパス（`--reference`）と出力先（`--output`）を必須引数として解析する
2. 結果JSONスキーマ:
   - 計測結果1件が、所要時間、RTF、ピークメモリ、出力パス、ウォーターマーク検出結果の
     必須キーを全て含むことを検証する
   - エンジン呼び出しを偽実装（注入した関数）に置き換えた状態で、評価文リストに対し
     文数分の結果が生成されることを検証する

### 期待する失敗

- `scripts/poc_generate.py` が存在しない、または対象関数が未実装のため、
  `ModuleNotFoundError` / `ImportError` / `AttributeError` あるいはアサーション失敗で
  全テストが失敗する。この失敗の実出力を確認してからGREENへ進む。

## 5. GREEN（最小実装）

- 引数解析（`argparse` 等の標準ライブラリ）・計測ループ・JSON出力の最小実装を書く。
- エンジン呼び出しは注入可能な関数（引数またはパラメータとして渡せる形）に分離し、
  単体テストでは偽実装を注入する。実モデルのimportはスクリプト実行時のみ行い、
  テスト収集時にimportされない構造にする。
- テストを通す以上の機能を追加しない。

## 6. REFACTOR（許容範囲）

- 計測部の関数分割まで。機能追加は禁止。
- テストが通ったままであることを毎回確認する。

## 7. 検証（完了条件）

リポジトリルートの仮想環境（`.venv`、Python 3.11）で以下を実行し、実出力を報告に含める。

```bash
pytest tests/unit/test_poc_args.py -q
```

- 完了条件: 上記テストが全件成功する。
- 実モデルでの実行確認は本タスクの範囲外（ClaudeがP0-C2で実施）。

## 8. 停止条件（該当したら作業を止め、実出力とともに報告する）

- 本契約の記述と `docs/implementation-plan.md` / `docs/system-specification.md` の間に
  矛盾・算術ミス・実装不能な指示を発見した場合（黙って直さない）
- 所有ファイル以外を変更しなければテストを通せないと判明した場合
- 依存パッケージの不足・import不能など、依存導入（Claudeの責務）が必要になった場合
- サンドボックス制約・権限エラーで作業が進められない場合
- 同じテスト失敗が2回の修正試行後も解消しない場合

## 9. 報告フォーマット

完了時（または停止時）に以下を報告する。

1. 変更ファイル一覧（所有2ファイルのみであること）
2. `pytest tests/unit/test_poc_args.py -q` の生出力
3. ブロッカーの有無と内容
4. 契約からの逸脱があればその理由（原則として逸脱禁止）

## 10. Git・依存導入の禁止（再掲・厳守）

Codexは本タスクにおいて、いかなるGit操作も依存関係の導入・変更も行わない。
コミットはClaudeがレビュー後に所有ファイルを個別に `git add <file>` して行う。
